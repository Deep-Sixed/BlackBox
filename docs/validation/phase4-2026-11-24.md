# Phase 4 validation — isolated integration (2026-11-24)

The record of validating BlackBox `0.8.0.dev0` (PR #37) on its production host
before the 0.8.0 release. Host-specific details (paths, inventories, other
services' findings) are kept in the operator's private evidence archive. This is
the public summary.

**Result: passed.** One deployment-blocking defect in the systemd unit template
was found, fixed (`03d91cb`), covered by a regression test and re-verified.

## Method

- **Staging service:** the production unit template with names changed, running
  as the service account on a separate socket, database, configuration, backup
  directory and groups.
- **Packages:** installed from the lockfile with hash checking; Python 3.14.4.
- **Callers:** tests ran over the real Unix socket as real accounts, plus
  disposable rootful Podman containers.
- **Cleanup:** all staging resources were removed afterwards and the host was
  compared against a pre-flight baseline.

## Follow-ups (non-blocking)

- Reuse connections in the writer thread. Per-request connection setup and
  schema validation dominate single-event latency.
- Check the `correlation_id` query plan.
- Name the cause when a database is refused because a parent directory is
  shared. The CLI currently reports `database_unavailable`, and the runbook
  explains it.
- Metric counters are in-process and reset on restart (expected).
