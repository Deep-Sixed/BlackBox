# Phase 5 — production deployment (2026-11-24)

The record of deploying BlackBox `0.8.0` as an independent production service
on its host. Host-specific details (inventories, other services' state,
evidence files) are kept in the operator's private archive. This is the public
summary.

**Result: deployed and verified.** No critical check failed, so the rollback
was not needed.

BlackBox runs **alongside** EVECOR's Flight Recorder. No production consumer
was redirected to it, and no event producer is enabled yet. Each producer needs
separate approval.

## Before deployment

- **Gateway check.** One authorized tool call went through the ContextForge
  gateway's full request pipeline using a dedicated broker identity. Flight
  Recorder recorded exactly one matching receipt. This closed the checkpoint
  left open in Phase 4.
- **Baseline.** A fresh host baseline was taken first, covering units,
  listeners, accounts, containers, Flight Recorder storage ownership and modes,
  and disk.

## Deployment

| Item | State |
| --- | --- |
| Release | `v0.8.0` wheel, checksum-verified, dependencies installed from the lockfile with `--require-hashes` (6 packages) |
| Service | `blackboxd.service` as `blackbox-svc`, enabled, `Restart=on-failure` |
| Transport | Unix socket `/run/blackbox/blackbox.sock` (`blackbox-svc:blackbox-clients` 0660); no TCP listener |
| Storage | `/var/lib/blackbox/db` (0700), database 0600, schema v5 |
| Credentials | Principals file `root:blackbox-svc` 0640 (hashes only); token files 0600 in a 0700 directory outside the repository |
| Principals | `anchor` (read own, no metrics) and `operator` (read all, metrics). No writers. |
| Git observation | Allowlist absent (empty) |
| Hardening | Syscall filter including the Phase 4 `@chown` fix; `systemd-analyze security` **0.5 SAFE**; no seccomp violations |
| Timers | `blackbox-backup.timer` (nightly) and `blackbox-anchor.timer` (every 15 min), both enabled |

The anchor job is a **system** unit running as the anchor owner, not a user
unit. A user manager started before a new group membership keeps its old
groups, so a user unit could not open the socket. The template in
[`deploy/systemd`](../../deploy/systemd) now uses that form. For the same
reason, the backup reader gets read access to the copies through an ACL.

## Initial measurements (not benchmarks)

Production host, very light load (a few dozen requests):

| Measure | Result |
| --- | --- |
| Single-event ingest | p50 ≈ 5 ms; slowest 128 ms (first write) |
| Batch of 100 events | 189 ms |
| Get by id, page queries | 5–7 ms |
| Integrity check (≈300 receipts) | 23–31 ms |
| Memory | cgroup 27 MB (peak 30 MB), RSS 46 MB |
| Database | 428 KiB for 101 events and 311 receipts |

These measurements come from too few requests to predict behaviour under
producer load. Measure again once the first producer is approved.

## Follow-ups

- **First producer.** Approve it separately, then give it its own principal.
- **External health monitoring.** BlackBox has no external health monitor yet.
  Consider adding a push check for `ready` and the timer results, as other
  local services have.
- **Phase 4 follow-ups still open:** writer-thread connection reuse, the
  `correlation_id` query plan, and a clearer error when a parent directory is
  shared.
